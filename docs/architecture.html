StayWiseAI Architecture

A natural-language housing recommendation engine. The user describes the home they want; a five-stage pipeline parses intent, scores neighborhoods, retrieves listings, ranks them against the request, and explains every match. This document covers the whole system — topology, runtime flow, the pipeline internals, data contracts, and operations.

1 Overview

Two deployable parts talk over a single JSON/HTTP boundary.

Frontend

Next.js 15 (App Router) · React 18 · TypeScript. Renders the search experience, validates payloads with Zod, and calls the backend. Runs on :3000.

Backend

FastAPI · Python 3.11 · a LangGraph-style agent pipeline. Parses the query and produces ranked, explained recommendations. Runs on :8000.

The defining design choice is graceful degradation: every external dependency (Anthropic, a real-estate provider, Postgres, LangSmith, Sentry) is optional. With no keys configured the app runs in demo mode — heuristic agents over a built-in San Francisco catalog — so it is fully runnable on a laptop with zero accounts.

The route handler is async and awaits the pipeline directly — no nested event loop.
Why CORS is the outermost middleware. Middleware added last wraps first. CORS sits outermost so that error and 429 responses also carry Access-Control-Allow-Origin. Otherwise the browser blocks the error body and the failure surfaces unhelpfully as “Failed to fetch.”

Three entry points live in graph.py: arun_pipeline() (async, used by the route), run_pipeline() (sync wrapper for tests), and build_graph() (reserved for a full LangGraph compilation). All share the same async stage implementation.

6 Scoring & ranking math

This is what makes results respond to the query rather than returning a fixed list.

Base listing score — score_listing()

A weighted blend, each component clamped to 0–100:

ComponentWeightFormula
Price fit30%closeness of price to budget_mid
Size20%square_feet / 1000 × 100
Neighborhood25%neighborhood_score × 100
Amenities15%fraction of must_haves matched
Freshness10%placeholder (50) — reserved for listed_date

Query-aware ranking — rank_listings()

Wraps the base score with hard filters and preference boosts, then sorts descending:

# 1) Hard filters (drop, never reorder)
drop if price > budget_max × 1.1        # over budget
drop if bedrooms < bedrooms_min          # too small
# …falls back to ranking ALL listings if filters would empty the set

# 2) Preference boosts on top of the base score
if "cheaper"  in tags: score += (1 − price_pos) × 18   # favor low price
if "premium"  in tags: score += price_pos × 18         # favor high price
if "spacious" in tags: score += size_pos × 18          # favor large sqft
if "quiet"    in tags: score += +12 if 'quiet' in amenities else −5
if "transit"  in tags: score += +12 if 'near_transit' in amenities else −5

# 3) sort by final score, best-first

price_pos and size_pos are min–max normalized across the candidate set, so “cheaper” and “bigger” are relative to what is actually available.

Observed behavior. “cheaper 1 bedroom” floats the $2,950 unit up; “bigger home with parking” floats the 1,700 sqft home up and filters to parking; “quiet under $4000” boosts quiet-tagged listings and pushes the $4,100 unit below budget; “premium luxury 2 bed” filters out 1-beds and ranks the most expensive first.

Neighborhood score — score_neighborhoods()

score = 0.6 × (walk_score / 100) + 0.4 × (1 − min(median_price / 1,000,000, 1))

Order matters: CORS wraps everything so all responses — including errors and 429s — get CORS headers.
  • CORS — allows localhost:3000 and the production origin.
  • Rate limiter — in-memory sliding window, 60 requests/hour per client IP (dev-grade).
  • ExceptionMiddleware — converts uncaught exceptions to a clean JSON 500.

The real-estate client & demo mode

RealEstateAPIClient uses httpx with retries and exponential backoff and honors HTTP 429. When REAL_ESTATE_API_KEY is unset it short-circuits to a curated 12-home San Francisco catalog (each tagged with amenities plus quiet / near_transit signals), so the pipeline never makes a network call it can’t satisfy.

11 Persistence & observability

Persistence

SQLAlchemy 2 engine + SessionLocal (db/engine.py). The only persisted entity today is Click (affiliate tracking). State is otherwise computed per request; graph/checkpointer.py reserves a spot for LangGraph checkpointing of conversation threads.

Observability

init_observability() wires Sentry (errors) and LangSmith (LLM traces) at startup — strictly best-effort, wrapped in try/except so a missing library or key never blocks boot.

13 Design decisions & rationale

Graceful degradation

Every external dependency is optional with a deterministic fallback, so the app is always runnable and demoable.

Async-native route

The route awaits arun_pipeline() directly instead of spinning a nested event loop — avoiding the “event loop already running” class of bug.

CORS outermost

Guarantees error and rate-limit responses carry CORS headers, so client errors are legible instead of “Failed to fetch.”

Validation at both ends

Pydantic on the server, Zod on the client — the JSON contract is enforced symmetrically.

Pure vs. LLM stages

Neighborhood/retrieval/scoring are deterministic and unit-testable; only intent and explanation are LLM-capable, keeping cost and nondeterminism contained.

Relative preferences

“cheaper” / “bigger” are normalized across the candidate set, so ranking is meaningful regardless of the absolute price range available.
